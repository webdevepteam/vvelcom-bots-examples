# Списки покупок и дел из голосовых (Yandex Cloud Functions + GigaChat)

Бот для семейной или рабочей группы в VVelcom. Человек записывает голосовое: «купить молоко, два батона и килограмм яблок, и завтра позвонить сантехнику». Бот распознаёт речь, GigaChat раскладывает её по спискам, и в чат приходят сообщения-чекбоксы: «🛒 Список покупок» и «📋 Список дел». Каждый пункт — кнопка, нажатие отмечает «готово» ✅.

- Распознавание речи — метод Bot API [`transcribeVoice`](../../docs/api/bot-api.md) (тот же сервис, что «→T» в приложении). Отдельный ключ для распознавания не нужен.
- Разбор просьбы — GigaChat по **одному ключу владельца бота** из переменных окружения. Там же задаются модель и **промпт**: какие списки вести (покупки, дела, вещи в поездку — что угодно). Модель сама определяет, к какому списку относится просьба.
- Настроек в самом боте нет: всё меняется в переменных функции. Чтобы ключ не тратили чужие, бота можно ограничить своими чатами (`ALLOWED_CHAT_IDS`).
- Хранилище — JSON-файлы в бакете Object Storage, примонтированном к функции. В каждом чате хранятся последние 10 списков, более старые удаляются.

## Как пользоваться

### Составить список

- **В группе** бот слышит только обращённые к нему сообщения (правило платформы), поэтому:
  - запишите голосовое и **ответьте на него** сообщением `@ник_бота`;
  - или ответьте голосовым на любое сообщение бота;
  - или напишите текстом: `@ник_бота молоко, хлеб, 2 кг яблок` или `/add молоко, хлеб`.
- **В личном чате** — просто голосовое или текст, без упоминаний. Это ваши личные списки.

Бот пишет «🎙 Слушаю голосовое…», затем заменяет это сообщение на расшифровку и итог («🛒 Список покупок: новый, 5 п.») и присылает списки-чекбоксы.

### Изменить список

**Ответьте (свайп) на список бота** голосом или текстом: «убери хлеб, добавь сыр». В группе упоминать бота не нужно, это ответ на его сообщение.

- Правка не переписывает старый список, а создаёт **новый на его основе** («На основе списка от 15 окт.»). Прежний остаётся в истории (`/lists`): можно открыть, посмотреть, что заказывали тогда, ответить на него — и получить новый список на его основе.
- Отметки ✅ у оставшихся пунктов сохраняются. Если сказать «начни заново», «сбрось галочки», «закажем то же самое», отметки снимутся.
- Можно попросить и другой вид: «сделай из этого список дел».
- Без ответа на конкретный список («@бот добавь сыр») модель выбирает подходящий среди трёх последних.

### Кнопки и команды

Меню — кнопками: в личном чате после `/start` внизу появляется клавиатура «📝 Последний список», «🗂 Мои списки», «📊 Статистика», «❓ Помощь». Под справкой (`/help`, и при добавлении в группу) — те же действия inline-кнопками: в группе бот видит только их и команды. Команды остаются для меню «/» и для тех, кто привык:

| Команда | Что делает |
|---|---|
| `/add <текст>` | составить или изменить список текстом (в группе — без `@`) |
| `/list` | последний список (чекбоксы) |
| `/lists` | последние 10 списков: кнопки «🛒 Список покупок · 15.10, 14:32 · 7 п.», нажатие открывает список |
| `/stats` | расход токенов: в этом чате, всего у бота, остаток пакетов по ключу |
| `/help` | для чего бот (`BOT_ABOUT`) и как им пользоваться |
| `/id` | ID этого чата — для `ALLOWED_CHAT_IDS` (не в меню) |

Команды для кнопки «Меню» бот регистрирует сам (`setMyCommands`) при `/start` и при добавлении в группу.

## Настройка под себя: промпт

Что за списки ведёт бот, задаёт `BOT_PROMPT`. Это только «роль» и виды списков: формат ответа (JSON с операциями) код добавляет сам, его в промпте писать не нужно. По умолчанию — покупки и дела:

```
Ты помощник семьи в общем чате: ведёшь списки покупок и списки дел.
- Покупки … — список «Список покупок», эмодзи 🛒. В note — количество с единицами.
- Дела … — список «Список дел», эмодзи 📋. В note — срок или кто делает.
- Если в одной просьбе и покупки, и дела — раздели их на два списка.
```

Примеры своих промптов:

- только покупки: `Ты ведёшь список покупок для семьи. Название — «Список покупок», эмодзи 🛒. В note — количество с единицами.`
- сборы в поездку: `Ты помогаешь собраться в поездку. Вещи — «Взять с собой» 🧳, дела перед отъездом — «Перед выездом» ✅.`

Перевод строки в переменной — `\n`. У переменных функции общий лимит 4 КБ, поэтому длинный промпт положите файлом рядом с `index.js` и укажите `BOT_PROMPT_FILE=./prompt.txt`.

`BOT_ABOUT` — первая строка `/help`, например `🛒 Я веду список покупок семьи Ивановых.`

## Доступ только для своих

Ключ GigaChat один на всех, поэтому для семейного бота задайте `ALLOWED_CHAT_IDS` — ID своей группы и личных чатов через запятую. В чужом чате бот отвечает «🔒 Это частный бот. ID этого чата: …» и ничего не делает. Узнать ID: отправьте `/id` в нужном чате (в группе — `/id@ник_бота`), бот ответит «ID этого чата: …». Добавьте ID в переменную и сохраните новую версию функции. Пока переменная пустая, бот работает в любом чате.

## Как это устроено

- Вебхук VVelcom ждёт ответ 10 секунд, а распознавание и GigaChat работают дольше. Поэтому вебхук отправляет «Слушаю…», запускает **эту же функцию асинхронно** (`?integration=async`) и сразу отвечает `200`. Задача подписана HMAC от `VVELCOM_WEBHOOK_SECRET`, чужую задачу публичная функция не выполнит. Если асинхронный запуск не удался, задача выполняется прямо в вебхуке.
- Модель получает промпт, до трёх последних списков (с отметками) и список, на который ответили, и отвечает JSON-операциями: `new` — новый список, `edit` — новый на основе указанного (`reset` — снять отметки). Одна просьба может дать несколько операций (покупки и дела сразу).
- Распознаются только голосовые, записанные в приложении (кнопка микрофона). Музыку и другие аудиофайлы платформа не передаёт как `voice`, бот на них не реагирует.
- `transcribeVoice` ждёт результат до ~45 с. Если распознавание ещё идёт, функция повторяет вызов. Голосовое можно распознать в течение часа после события.
- Отметки «готово» обрабатываются прямо в вебхуке (`callback_query` → `editMessageText`), все показанные копии списка обновляются.

Структура `DATA_DIR`:

```
stats.json                      расход токенов всего бота
chats/<chatId>/chat.json        индекс последних списков, статистика чата
chats/<chatId>/lists/<id>.json  пункты списка с отметками, id показанных сообщений, на основе какого списка
```

Списки, сохранённые прежней версией бота (только покупки, с ключами пользователей), читаются как «🛒 Список покупок». Файлы `users/*.json` с ключами пользователей больше не нужны — их можно удалить из бакета.

## Деплой

1. Создайте бота у [@VVbotMother](https://uvvel.com/@VVbotMother) (`/newbot`) и получите токен.
2. Получите ключ GigaChat: [личный кабинет](https://developers.sber.ru/studio) → проект GigaChat API (для физлица есть бесплатный пакет токенов) → «Настройки API» → «Получить ключ» → «Ключ авторизации».
3. Создайте бакет Object Storage и функцию в [Yandex Cloud Functions](https://yandex.cloud/ru/docs/functions/):
   - среда `nodejs22`, точка входа `index.handler`;
   - **таймаут 300 с** (распознавание + GigaChat), память 256 МБ;
   - сервисный аккаунт с ролью `storage.editor` на бакет; бакет примонтирован в `/function/storage/shopping` (не только для чтения);
   - функция публичная (`allow-unauthenticated-invoke`), иначе ни вебхук, ни асинхронный запуск не дойдут;
   - переменные из `.env.example`; `VVELCOM_BOT_TOKEN`, `VVELCOM_WEBHOOK_SECRET`, `GIGACHAT_AUTH_KEY` — из Lockbox.
4. Загрузите `index.js`, `package.json` и `russian_trusted_root_ca.pem` ([сертификат Минцифры](https://developers.sber.ru/docs/ru/gigachat/certificates): Сбер подписывает GigaChat российским УЦ), и `prompt.txt`, если промпт в файле.
5. Зарегистрируйте вебхук:

```bash
curl -X POST "https://apibots.vvelcom.online/bot$VVELCOM_BOT_TOKEN/setWebhook" \
  -H "Content-Type: application/json" \
  -d "{\"url\":\"https://functions.yandexcloud.net/<FUNCTION_ID>\",\"secret_token\":\"$VVELCOM_WEBHOOK_SECRET\"}"
```

6. В @VVbotMother задайте описание бота, например: «Веду списки покупок и дел нашей семьи из голосовых».

Поменять промпт, модель или список чатов — новая версия функции с другими переменными, код трогать не нужно.

## Переменные

| Имя | По умолчанию | Описание |
|---|---|---|
| `VVELCOM_BOT_TOKEN` | — | токен бота (Lockbox) |
| `VVELCOM_WEBHOOK_SECRET` | — | `secret_token` вебхука, им же подписываются асинхронные задачи (Lockbox) |
| `GIGACHAT_AUTH_KEY` | — | «Ключ авторизации» GigaChat (Lockbox) |
| `GIGACHAT_SCOPE` | определяется по ключу | `GIGACHAT_API_PERS`, `GIGACHAT_API_B2B` или `GIGACHAT_API_CORP` |
| `GIGACHAT_MODEL` | `GigaChat` | модель: `GigaChat`, `GigaChat-Pro`, `GigaChat-Max`, `GigaChat-2`, `GigaChat-2-Pro`, `GigaChat-2-Max` |
| `BOT_PROMPT` | покупки и дела | какие списки вести (см. «Настройка под себя») |
| `BOT_PROMPT_FILE` | — | файл с промптом вместо `BOT_PROMPT` (путь от `index.js`) |
| `BOT_ABOUT` | текст по умолчанию | первая строка `/help` — для чего бот |
| `ALLOWED_CHAT_IDS` | — (любой чат) | ID чатов через запятую, где бот работает |
| `DATA_DIR` | `/function/storage/shopping` | папка примонтированного бакета |
| `LISTS_KEEP` | `10` | сколько последних списков хранить в чате |
| `BOT_USERNAME` | из `getMe` | ник бота без `@` |
| `TIME_ZONE` | `Europe/Moscow` | часовой пояс дат в списках и статистике |
| `GIGACHAT_CA_PATH` | `./russian_trusted_root_ca.pem` | PEM российского УЦ |
| `GIGACHAT_INSECURE_TLS` | — | `true` — не проверять сертификат (только для отладки) |
| `GIGACHAT_TIMEOUT_MS` | `30000` | таймаут ответа GigaChat |
| `LIST_MAX_TOKENS` | `1500` | предел длины ответа модели |

## Ограничения примера

- В кнопки помещаются 40 пунктов (лимит 20 рядов по две кнопки). Остальные показываются текстом в сообщении.
- Файлы в бакете пишутся по схеме «прочитал → изменил → записал». Если два человека в одну и ту же долю секунды отметят разные пункты, одна отметка может потеряться. Для большой нагрузки берите базу (YDB) вместо файлов.
- Защита от повторной доставки события хранится в памяти контейнера и при холодном старте обнуляется.
- Распознавание — до 30 голосовых в час на бота (лимит платформы).
- Публичного режима (свой ключ GigaChat у каждой группы) в этой версии нет.
